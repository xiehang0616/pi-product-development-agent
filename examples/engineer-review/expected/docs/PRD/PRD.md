# 工艺资料复核演示 PRD

状态：待确认（教学对照稿） · 版本：v1.0 · 创建/更新日期：2026-09-14。
来源：[初始需求](../../../input/brief.md)与[教学用确认消息](../../../walkthrough.md)。负责人/待确认人：练习使用者。
阻塞：实现方案与技术栈未确认；本文不证明原工程师系统具备这些能力。

## 目标与范围

让工程师把文本中的资料信息整理为可复核的字段建议，并在明确权限和版本条件后应用。成功标准是以下需求与用例能够形成对应关系；实际产品成功率、节省时间和模型质量暂无数据。

本阶段规划文本输入、建议展示、编辑、复核、应用和异常处理。不含真实图纸识别、加工参数推荐、真实模型接入、生产部署、双人复核或其他系统模块。

## 规则来源

AI 建议、人工确认和结果查看来自初始需求；下表中的具体字段、角色和状态来自教学用确认消息。它们只作为本示例的约定，真实项目需重新确认。

## 需求与验收条件

| ID | 需求 | 验收条件 |
| --- | --- | --- |
| REQ-01 | 项目与角色隔离 | 工程师可在授权项目申请、复核、应用；只读查看者只能查阅；未登录或跨项目访问由服务端拒绝，不泄露内容 |
| REQ-02 | 字段与依据 | 仅建议资料编号、材料名称、备注；逐字段显示依据；无依据时留空并提示；项目、权限、记录标识和版本不可由 AI 写入 |
| REQ-03 | 人工复核 | 初始状态为待复核；工程师复核后为已复核；再次编辑回到待复核；放弃后作废；待复核和已作废均不能应用 |
| REQ-04 | 版本一致性 | 申请时保存原记录版本；应用时比对最新版本；版本冲突使建议作废并提示重新申请，不覆盖新记录 |
| REQ-05 | 一致提交与防重复 | 成功时记录写入、建议变为已应用、审计事件一致提交；任一失败不保留部分写入；重复应用返回既有结果，不再次写入 |
| REQ-06 | 异常与恢复 | 模拟超时或格式错误时显示错误且不产生可应用建议，保留输入以便重试；应用权限失效时拒绝；普通写入失败保持已复核并允许重试 |
| REQ-07 | 追溯 | 保存建议标识、原记录版本、操作者、复核/应用时间与结果；审计访问受项目权限限制，不记录凭据或不必要的原文 |

## 角色与流程

| 角色 | 可做什么 | 不可做什么 |
| --- | --- | --- |
| 授权工程师 | 在授权项目申请、编辑、复核、应用与放弃建议 | 绕过版本检查，修改 AI 白名单外的字段 |
| 授权只读查看者 | 查阅授权项目的记录、建议与处理状态 | 申请、修改、复核或应用建议 |
| 未登录/未授权用户 | 无项目数据访问权限 | 读取或修改记录、建议与审计记录 |

主流程：输入文字 → 模拟生成建议 → 查看依据并编辑 → 人工复核 → 应用前检查 → 成功写入与审计。

| 当前状态 | 事件/条件 | 下一状态 | 数据影响 |
| --- | --- | --- | --- |
| 无建议 | 生成成功 | 待复核 | 只保存建议与来源版本 |
| 待复核 | 人工完成复核 | 已复核 | 记录复核者和时间 |
| 已复核 | 修改建议 | 待复核 | 原复核不再有效 |
| 待复核/已复核 | 放弃 | 已作废 | 不改变正式记录 |
| 已复核 | 应用时发现版本冲突 | 已作废 | 不改变正式记录 |
| 已复核 | 权限有效、版本相同且提交成功 | 已应用 | 正式记录、建议和审计一致提交 |
| 已复核 | 普通写入失败 | 已复核 | 无部分写入，允许重试 |
| 已应用 | 重复应用 | 已应用 | 返回既有结果，无新增写入 |

权限失效时拒绝操作，不授予任何新权限。获取建议时的加载/错误是请求状态，不额外增加建议生命周期状态。
