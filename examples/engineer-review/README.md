# 工程师系统：AI 辅助录入与人工复核

这个示例演示如何用产品研发总控助手，把“让 AI 帮我录入资料”细化为可交接的需求、任务与验收用例。

流程参考项目维护者提供的工程师系统资料，保留“AI 提建议、人工复核、权限隔离、结果可追溯”的设计问题。项目名称、对象、输入和确认消息均为教学构造，未收录原始资料、在线系统地址、邀请码、真实图纸或原项目测试数据。

**这是文档阶段的示例。没有示例应用、真实模型调用、Pi Agent 实跑记录或已通过的业务测试。** `expected/` 中的文件是人工编写的对照样稿，帮助你判断输出是否充分；措辞和章节可以不同。

## 文件与阅读顺序

| 文件 | 用途 |
| --- | --- |
| [input/brief.md](input/brief.md) | 提供给 Agent 的不完整需求；故意保留权限、确认和并发问题 |
| [walkthrough.md](walkthrough.md) | 首轮应发现的问题、三个推进方案，以及教学用确认消息 |
| [expected/docs/PRD/PRD.md](expected/docs/PRD/PRD.md) | 按示例确认消息整理的需求与验收基线 |
| [expected/docs/项目状态/项目状态.md](expected/docs/项目状态/项目状态.md) | 研发任务、依赖、待确认事项与后续文档安排 |
| [expected/docs/测试Case/测试Case.md](expected/docs/测试Case/测试Case.md) | 映射到需求的功能验收用例，实际结果全部留空 |

## 第一步：准备独立练习目录

1. 新建空文件夹 `engineer-review-demo`，用 VS Code 打开它。
2. 在里面新建 `docs/PRD/`，将 [input/brief.md](input/brief.md) 复制为 `docs/PRD/PRD.md`。
3. 按仓库的[使用方式](../../README.md#使用方式)，将 [SYSTEM_PROMPT.md](../../SYSTEM_PROMPT.md) 配置到 Pi Agent。

只复制输入文件。不要把 `expected/` 预先放进练习目录，否则 Agent 看到的就不是不完整需求。这个练习不需要模型 API Key、真实图纸或线上环境；与 Agent 对话本身仍需要你已有的 Pi Agent 配置。

## 第二步：启动需求检查

将下面的消息发给 Agent：

```text
请检查当前项目和 docs/PRD/PRD.md，协助完善“AI 辅助录入与人工复核”需求。

本轮只做需求盘点，不编写应用代码，不选择框架或模型，不调用外部系统。
先报告项目实际状态，列出最影响后续设计的三个问题，给出三个可行的推进方案并推荐一个。
区分输入中已有的需求、你的建议和待确认事项。
本轮不要覆盖原文件，等我确认范围后再整理文档。
```

对照 [walkthrough.md](walkthrough.md) 的首轮检查点。Agent 应先发现人工确认含义、权限范围与版本冲突等缺口，不应直接声称已有应用或测试已通过。

## 第三步：演练确认与任务拆解

阅读 walkthrough 中的“教学用确认消息”，确认它适合本次练习后再发送。这条消息会授权更新练习目录里的 PRD，并约定演示规则。它不是原工程师系统的正式产品决策。

Agent 随后可以整理以下三个文件：

```text
docs/
├── PRD/PRD.md
├── 项目状态/项目状态.md
└── 测试Case/测试Case.md
```

逐项对照 `expected/`：是否明确了谁能确认、哪些字段可以写入、旧版本结果如何处理、失败后如何恢复，以及每条用例对应哪个需求。

## 第四步：验收这一轮文档

- [ ] AI 建议和正式记录有明确边界；应用必须经过人工复核。
- [ ] 权限在服务端校验，不能仅隐藏前端按钮。
- [ ] 旧版本结果和重复应用都有处理规则。
- [ ] 每项研发任务有交付物、依赖与验收条件。
- [ ] 用例能追溯到需求，未运行的用例明确标记“未执行”。
- [ ] 技术栈、模型选择和质量指标仍如实标记待确认。

这些勾选项检查的是文档覆盖情况，不代表软件功能已验证。完成后，可以另行确认产品设计与技术方案，再让 Agent 实现和执行测试。该示例没有提供后续阶段的预设结论。

## 为什么只展示三个文档

仓库的 System Prompt 支持更完整的文档体系，但首轮不必批量填满所有目录。本例停在需求与任务交接阶段；产品设计、Agent 需求、Design、模型评测与其他专项的启动条件见[项目状态](expected/docs/项目状态/项目状态.md)。
